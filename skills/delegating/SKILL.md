# delegating 委派与协调

目标：让该外包的工作落到合适且可续用的 worker，并对它的过程与结论保持可证伪的掌握——派完就等不算委派。

## 该不该派
- 判据是过程／结论比：为了拿到这个答案，先要趟多少不属于答案的东西。趟得多的交出去，只回收结论与指针，不回收原始材料与过程。
- 能拆成互不依赖子任务的重活，拆开并行外包；相互独立的子任务在同一响应内并行派发。
- 派发的固定开销——写自足 prompt、重建背景、等待、核实返回——高于任务本身时自己做。

## 续用还是重新开始
- 派发前先盘点已有 worker 的问题域与局部背景；同一问题线的后续工作回到原 worker。
- 旧 context 仍适用且能减少背景重建时续用；任务换域、前提已变、旧 context 会误导，或需要独立审查时重新开始。

## prompt 形态
- 隔离是双向的：新建 worker 的首次 prompt 自足且带必要 context，worker没有你的context，代词必须交代清楚；续用 worker 只补增量 context，让已有背景继续承担上下文。
- 给执行器的求确定，减少它自由发挥的面；给审查者与高判断 sub-agent 的求目标——把要回答的问题、证据、边界给足，不把它锁进机械步骤。
- 交代清楚它的用户是你：需要你才能回答的问题让它问，不要让它猜着往下做。
- 新建 worker 时显式给出模型与 effort，不靠默认继承；续用时沿用原配置，配置与新任务不相容时重新开始。
- 用户已给定 sub-agent 需求和 prompt 时，逐字执行，不增删要求。

## 派出去不等于交出去
状态位只说明它活着，不说明它在干活，更不说明它干得对。进度与质量以产物为准——文件、计数、日志、进程——不以状态位或它的自报为准。派之前想清楚这活做成什么样算成；拿不到那个样子就接管，不是等它自己说完。

## 返回怎么核
返回是未经验证的断言，可能不完整、不准确或偏乐观：数字与事实采用前须回原始出处核对；它给出的理由同样是断言——"按简洁原则删掉了""这个已经够了"是它在给自己打分，不因其陈述而降低质疑强度。核对之后再看各结果之间有无冲突，确认无冲突再采用。

## 完成判据
每次续用或新建都指得到问题域与 context 依据；每条被采用的结论都指得到主 agent 亲自看过的证据——原始出处或产物，而非 sub-agent 的转述。

# Brainstorming

Expand the option space before evaluation so that an apparently obvious path does not hide a better one.

## Method

- When a request covers multiple independent topics or sub-items, split them first and brainstorm only the first sub-item.
- Diverge before converging: list independent hypotheses, questions, and explanatory angles before evaluating them.
- Use cross-domain analogies, reverse assumptions (what if the conclusion were opposite?), and alternative explanations to expose more options.
- When fidelity is insufficient, run a one-command throwaway calculation or toy example. Answer one question, record the conclusion, and discard the prototype.
- Rank candidates at convergence by feasibility, novelty, and evidence availability.

“Too simple to brainstorm” is an anti-pattern: obvious tasks are where better alternatives are easiest to miss.

## Gate

Finish brainstorming by converging before any execution. For substantial work, use `/grilling` to decide item by item; for a small task, state the intended work and expected conclusion clearly and obtain agreement.
